# KBO dataset provenance matrix

Audit date: 2026-09-10 (Asia/Seoul)

Scope: KBO-related factual inputs and derived calibration outputs currently present in `data/`, `reports/`, and `tools/balance_lab/` on the public repository. This document is descriptive provenance metadata; it does not grant redistribution rights over third-party data.

## Status labels

- **CONFIRMED**: directly documented in the repository and/or verifiable from an identified upstream source.
- **INFERRED**: strongly supported by file structure or arithmetic, but not explicitly preserved as source metadata.
- **OPEN**: source, snapshot date, sample definition, or redistribution permission is not sufficiently documented.
- **PROJECT-DERIVED**: generated by this project's rating/calibration/simulation code rather than an official KBO evaluation.

## Metric definitions

For `kbo_2026_real_hitter_ratings_v2.csv`, v3, and v4, the files do not preserve denominator definitions. The stored values are arithmetically consistent with the following and should therefore be treated as **INFERRED until explicitly documented from the original ingestion step**:

- `target_hr_rate` = HR / PA
- `target_bb_rate` = BB / PA
- `target_k_rate` = SO / PA

For the frozen 2025 league target in `tools/pitcher_calibration/targets.py`, the derived metrics are reproducible from the stored totals:

- AVG = H / AB
- OBP = (H + BB + HBP) / (AB + BB + HBP + SF)
- SLG = (1B + 2*2B + 3*3B + 4*HR) / AB
- OPS = OBP + SLG
- BB%, K%, HR%, 1B%, 2B%, 3B% use PA as denominator
- BABIP = (H - HR) / (AB - SO - HR + SF)

## Source mapping and verification notes

### 2026 real-hitter snapshots

Project metadata in `kbo_2026_real_player_simulation_policy_v1.json` identifies the provider as **KBO official records** and describes the first batch as 30 high-PA first-team hitters. However, the historical CSV rows do not carry a KBO URL, query parameters, capture timestamp, PA/AB, game count, or source hash. The statement is therefore useful provenance evidence, but it is not enough to reconstruct the exact in-season snapshot.

The official KBO player-record service can be used for present-day verification:

- https://www.koreabaseball.com/Record/Player/HitterBasic/Basic1.aspx
- https://www.koreabaseball.com/Record/Player/HitterBasic/Basic2.aspx

Because 2026 is an in-progress season, current KBO values can differ from the historical targets in these files. Do not overwrite or reinterpret the stored calibration targets as final-season values without an explicit refresh.

### 2025 full-league pitcher-calibration target

`tools/pitcher_calibration/targets.py` explicitly records that the totals came from the 10 KBO regular-season team batting lines and that the source page identifies `koreabaseball.com` as its data source. A currently accessible secondary page reproduces the 2025 team batting table and identifies it as KBO data:

- https://www.yagoonara.com/en/team-stats/detail/2025/hitter

This is corroborating evidence, **not proof that this exact page was the historical ingestion page**. The exact collection URL and original access date remain OPEN.

## Redistribution / terms concern

KBO's current website terms should be reviewed before committing or redistributing copied KBO site data. The terms page includes restrictions on reproducing service information without prior consent, automated bulk collection without written consent or an official API, and collecting data/content for resale, redistribution, platform integration, or secondary processing:

- https://www.koreabaseball.com/Etc/Policy.aspx

This project does **not** interpret public visibility of a statistic as a grant of redistribution rights. Existing copied factual snapshots remain `OPEN` for redistribution unless the applicable source terms or permission for that exact dataset are documented.

## Unresolved provenance list

1. Original provider/page URL for each `kbo_2026_real_hitter_ratings_v1-v4` factual target snapshot.
2. Original access/capture date and time for each 2026 snapshot.
3. Per-player sample at capture time: G, PA, AB and, where applicable, HR/BB/SO raw counts.
4. Exact selection rule for the 30-player batch beyond the policy description `high-PA first-team hitters` (threshold/rank/tie handling are not preserved).
5. Exact historical collection page used for the 2025 10-team totals in `tools/pitcher_calibration/targets.py`.
6. Redistribution/license permission applicable to each historical copied factual snapshot.
7. Empirical source, if any, for `NEUTRAL_BB`, `NEUTRAL_K`, `NEUTRAL_HR`, `NEUTRAL_AVG` and related performance baselines in pitcher parameter files.
8. No separate real-world physical pitch-velocity reference/distribution dataset was found in the audited repository tree. Existing `velocity` means/SDs are simulation rating-scale parameters, not documented km/h or mph datasets.

## Future ingestion checklist

Before committing a new real-world baseball dataset:

1. Record provider and exact source URL.
2. Record access/capture timestamp with timezone.
3. Record league, season, regular/postseason scope, and whether the season is complete or in progress.
4. Record sample restrictions and selection logic (for example minimum PA/IP, top-N rule, positions, qualified-only status).
5. Preserve raw denominators/counts required to recompute rates where practical.
6. Define every non-obvious metric and denominator.
7. Separate third-party factual inputs from project-derived ratings, Monte Carlo outputs, fit/error fields and simulation policy.
8. Record transformation script/version or a reproducible derivation description.
9. Record whether source terms/license were checked and whether redistribution is permitted, prohibited, or unresolved.
10. If redistribution is unresolved, prefer source references plus transformation/retrieval instructions over committing copied bulk rows.
11. For in-season snapshots, preserve a capture date and enough raw counts to distinguish the snapshot from later official updates.
12. Never use a Git commit timestamp as a substitute for the original data access timestamp.
